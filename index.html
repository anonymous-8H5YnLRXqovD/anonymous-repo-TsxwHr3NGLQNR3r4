Compiling Large Multi-Modal Requirement Documents into Runnable Web Systems

From an Agentic Test-Driven Perspective

ISSTA 2026 Submission Anonymous Authors

Abstract

Large Language Models (LLMs) have significantly improved programming efficiency but suffer from "complexity walls" when requirements scale. When faced with multi-modal documents containing hundreds of scenarios, traditional agentic approaches often produce incorrect implementations or omit crucial constraints.

We propose ARC (Agentic Requirement Compilation), a framework that shifts the paradigm from stochastic code generation to rigorous requirement compilation. ARC parses multi-modal requirement documents (in a DSL format) into runnable web systems. It employs a bidirectional test-driven agentic loop: Top-down decomposition of requirements into verifiable interfaces, and Bottom-up code generation gated by generated test suites.

Methodology Overview

The ARC framework operates in two phases to ensure traceability and correctness:

  • Phase 1: Testable Architecture Construction. We use a Domain Specific Language (DSL) to model requirements as a graph. Agents perform a DFS traversal to synthesize database schemas, API definitions, and UI component stubs, while simultaneously generating Test Suites (Unit, API, GUI) for verification.
  • Phase 2: Constrained Code Generation. Code is implemented bottom-up. A gating mechanism ensures that no code is committed unless it passes the pre-generated tests, solving the hallucination problem in large-scale generation.

Prompt Engineering

Below are the key system prompts used in the ARC framework. We use a chain-of-thought approach for all agents.

Used to decompose the Requirement DSL into technical specifications.

SYSTEM: You are an expert Software Architect capable of translating ambiguous requirements into strict technical specifications. INPUT: A Requirement Node containing user stories and data constraints. TASK: 1. Analyze the dependencies of the current node. 2. Define the Database Schema (SQL) required. 3. Define the RESTful API endpoints (OpenAPI format). 4. Outline the Frontend Component structure (Vue.js/React). CONSTRAINT: Ensure all data fields mentioned in the requirement are present in the DB schema. ... [Full prompt content would be placed here]

Used to generate the UI code and the corresponding visual descriptions for multi-modal alignment.
